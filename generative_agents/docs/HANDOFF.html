AI 小鎮專題：Generative Agents 修改版

目前進度與交接說明（給 Codex 與專案成員）　｜　2026 年 11 月 19 日　｜　撰寫：Claude Code
一句話摘要：原版 Stanford Generative Agents 已改成可用 GPT-6 Luna（或 NVIDIA NIM）無人值守長時間執行、可部署到 Google Cloud 的版本，並建好 12 人與 4 人的新小鎮。所有功能都已用「假模型回答」離線驗證，但還沒有用真正的 API 跑過。下一步是：本機用 NIM 測 4 人小鎮 → 用 Luna 試跑並量出實際費用與速度 → 部署 Google Cloud 跑正式實驗。

1. 專案目標與限制

項目內容
性質大學專題，目標投稿研討會。可用 6 個月，預計 2 個月內完成主要工作。
主實驗12 位居民、50 個模擬天、GPT-6 Luna「省錢版」設定，在 Google Cloud 上約 5 倍速執行（約 10 個現實天）。
研究方向（暫定）「生成式代理人的長期行為」：原論文只跑 2 天，本研究觀察 50 天後人設是否一致、行為是否重複、關係網路與消息傳播如何演變。領域預設為人機互動（原論文發表於 UIST 2023），待指導老師確認。
預算OpenAI API 約 130 美元；Google Cloud 額度約 9,000 美元；另有新台幣 3,000 元備用。
語言與使用者溝通一律用繁體中文。模擬中的對話、想法、反思、每日近況用繁體中文；動作描述維持英文（原版程式依賴英文關鍵字）。

4. 尚未驗證與已知限制（請特別注意）

  1. 從未呼叫過真正的 API。所有費用、速度都是估算。真實模型可能不照原版要求的格式回答，造成較多重試或使用原版的備用答案。
  2. NIM 預設模型名稱未確認：meta/llama-3.3-70b-instruct、nvidia/nv-embedqa-e5-v5 是依網路資料選的範例，請到 build.nvidia.com 確認仍可用。NIM 免費帳號約每分鐘 40 次，僅適合功能測試。
  3. Luna 的 low 與 none 哪個便宜仍待實測：Artificial Analysis 顯示 Luna Low 每任務 $0.0051、Non-reasoning $0.0714（low 更便宜也更快），但那是長答案的測驗；本模擬的例行判斷答案很短，需實測比較（見第 6 節）。
  4. 估算的依據：每日呼叫次數來自「假模型」跑原版 25 人一天（約 6.4 萬次）。假模型決定聊天的機率是固定 30%，真實對話次數可能不同。
  5. 與原版的差異（論文需揭露）：平行處理使同一步中所有人看到的是步驟開始時的狀態；重要性評分快取（接續後會重新累積）；模型與思考程度不同；對話改繁體中文。完整清單在 NOTICE.md。
  6. 還沒有的東西：讀取新格式 movement_log 的視覺化回放畫面；研究用分析工具（居民訪談、社交網路、消息傳播、人設一致性）；Vertex AI（Gemini）支援。
  7. 原版地圖美術（PixyMoon、LimeZu）不在 repo 內，需要畫面時執行 scripts/fetch_assets.sh 下載，不可提交進 repo。

7. 給 Codex 的協作規則

Claude 與 Codex 會在同一個 repo 輪流工作。以下規則讓雙方不會互相覆蓋或破壞已驗證的東西。
  1. 分支：從 claude/nim-4-agents 開新分支（例如 codex/deploy-gcp）。不要直接改 claude/* 分支，也不要直接推 main；要合併時開 PR，由使用者決定。
  2. 金鑰：絕不把任何 API Key 寫進檔案、設定檔、commit 或對話。GCP 用 setup.sh 的隱藏輸入存進 Secret Manager；本機用環境變數。config.env 已在 .gitignore。
  3. 每次修改後執行測試並確認全部通過：
    cd generative_agents/reverie && ../.venv/bin/python -m pytest -q tests
  4. 請保持這些設計（改動前先與使用者確認）：
    • 動作描述維持英文（程式依賴 sleeping、bed、idle 等關鍵字與固定英文格式）。
    • 當機的步驟不存檔；FatalLLMError 必須是 BaseException。
    • 住家名稱含 's house 時必須含居民姓氏（原版的進門規則）。
    • 人物與地圖只改 scripts/build_tw12.py 後重新產生，不手改產出的 JSON。
    • 新增提示詞函式時，fake_cognition.py 也要加對應的假回答（否則空跑會報錯）。
    • 任何與原版的差異都補進 NOTICE.md（研究論文需要揭露）。
  5. 實驗紀錄：每次真實執行（不含空跑）請在 generative_agents/docs/RUN_LOG.md 新增一列：日期、模擬名稱、初始設定、模型與思考設定、模擬天數、現實耗時、花費、結果與問題。這是之後寫論文的依據。
  6. 交接：結束一段工作時，在 PR 或 RUN_LOG.md 寫下做了什麼、驗證到哪裡、遇到什麼問題，讓下一位（Claude 或 Codex）能直接接手。
  7. 不確定時先問使用者，尤其是會花錢的操作（真實 API 長時間執行、建立大型雲端資源）。

9. 主要風險

風險因應
真實模型格式錯誤多，行為品質差NIM 與 Luna 試跑時檢查報告；必要時對個別任務調高思考程度（GA_REASONING_OVERRIDES）
速度達不到 5 倍試跑量測；可延長現實時間、改用 low、提高同時呼叫數，或拉長每步秒數（需改走路邏輯）
超支一律設定 MAX_COST；先短跑再長跑
只跑一次無法下結論重複實驗（Google Cloud 額度＋Gemini，若額度適用）
研討會截止日第 2 週前與老師確認目標會議與日期
