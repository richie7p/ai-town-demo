# 規則對照與工程界線

內容依研究計畫 v5、22 頁教授簡報 v7。引擎版本 `demo-0.1.0` 僅用於驗證，不構成正式協定凍結。

## 時間與行動

`state.tick` 是已結算的時段數，0 為初始；絕對時段 1–12 為 D1，13–24 為 D2。所有提議與觀察固定於下一個時段的開始快照。原 state 不被修改，結算回傳新 state。

每個 actor 最多一個提議；缺少者以 wait 補齊。重複 actor 或未知 actor 拒絕整批，原狀態保留。未知行動、錯誤位置、錯誤來源等記 invalid，無重新抽取動作。demo 未模擬服務失敗或格式修復重試。

每時段 priority 僅由種子、時段與角色生成，與提議陣列順序無關。全部初始可用設備才可分配，同時段歸還或到期不提前增加供給。

## 對話

同對角色最多一個活躍對話。talk 在既有活躍對話中視為續談；只有新對話的 opening talk 能驗證有效發起。回覆須明確提供對話 ID、對方 ID 及來源訊息 ID。

同步互 talk 保留兩位共同發起者；後續首次對開場訊息的合法回覆，才驗證兩位。單純互發開場不算有效互動。回覆／合作依完成日累積互動日，同對同日封頂一次。

對話在兩個連續時段無新訊息，或一方離區後關閉。重新開場前的上一完整時段不得有此對的訊息／完成互動。此版不另設主動關閉 action，使用空白時段或離區關閉；正式版若增加主動關閉，須補充行動格式與相應測試。

若一人同時回覆、另一人移動，回覆依期初位置驗證，再因離區關閉。新的移動地點只影響下一時段。

## 邀請

邀請僅在設備所屬區域、雙方同區且 due 時段無衝突安排時送達，due 固定為 t+2。待處理與已接受邀請均保留兩位參與者的該時段安排；decline 解除後續安排衝突。

只有受邀者能在期限前 accept／decline。本 demo 要求回應時仍同區。到期必須發起者持有可用的正確設備並 work、受邀者 join 同一邀請，才產生一次 cooperation。任一條件缺失保留失敗；發起者合法使用設備仍可得到 solo work。

合作率只納入 due 已在觀察範圍內的合法邀請，沒有分母時為 null（UI 顯示 NA）。due 在場次末端之後者列行政設限。有效全零結果保留。

## 記憶

事件只對當時同區觀察者與參與者可見。此為 demo 採用的公共可見性政策，正式版應與提示／觀察範圍一併凍結。talk 的文字是「有人說了這段話」的事件，不會讓引擎當成已完成工作或設備事實。

查詢由當前位置、活動目標、收到訊息、待處理邀請建立，先於下一動作與對象選擇。近期事件按新到舊；較早事件排除最近 2 時段，依排序取最多 6 筆。容量不足按近期、舊事件的次序逐項保留；同分依較新時間與事件 ID 排序。不合可見範圍或未實際提供的引用，記 invalid。

所有來源是 observed_event；未實作獨立轉述知識庫或模型反思。當前邀請保存在世界狀態，與檢索資料分開。

## 紀錄與重播

每個 trace 保留：時段、期初及期末校驗、優先序、八份實際觀察／檢索、正規化提議、產生的事件 ID。

匯入會使用同版本引擎重新結算保存的提議，再比較完整事件、完整 trace 與狀態校驗；不呼叫策略或 API。整份驗證完成後才替換畫面。規則／順序若變更，需提高引擎版本，不能混合不同版本資料。

## 本次沒有證明的事情

- 合成資料的 A/B 差值不代表研究效果或檢定力。
- 有效互動及核心不直接等同友誼、信任或派系。
- 記憶出現在觀察中，不代表造成後續行為。
- 技術案例通過，仍不表示正式實驗已可啟動。
